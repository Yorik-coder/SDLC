# ADR-001: Логическое разделение FitBalance на слои

- **Статус:** Proposed — сверить с фактическим кодом проекта.
- **Дата:** 24.11.2026
- **Связанные требования:** REQ-FUNC-001–REQ-FUNC-012, REQ-REL-001, REQ-OBS-001.

## Контекст

FitBalance — автономное настольное приложение одного пользователя. Формулы, обработку дневников и работу с локальными данными нужно организовать так, чтобы изменение экрана не требовало переписывать предметные правила.

## Факторы решения

- работа без Интернета;
- проверяемость вычислений;
- отсутствие серверной части в SRS v0.2;
- ограниченный объём учебного проекта.

## Рассмотренные варианты

1. Логические слои Presentation, Application, Domain, Infrastructure в одном приложении.
2. Единый слой UI с расчётами и операциями хранения в обработчиках экранов.
3. Клиент-серверная архитектура с отдельным API.

## Решение

Предлагается вариант 1. Presentation отвечает за взаимодействие с пользователем; Application — за сценарии; Domain — за сущности и расчётные правила; Infrastructure — за локальное сохранение и технические операции. Направление зависимостей — к Domain; UI не работает с хранилищем напрямую.

## Последствия

- Положительные: расчётное ядро можно тестировать отдельно; меньше дублирования; проще заменить способ хранения.
- Отрицательные: необходимо поддерживать границы слоёв и интерфейсы.
- Нейтральные: конкретные язык и GUI-фреймворк остаются открытыми до сверки с репозиторием.

## Проверка

Проверить, что обработчики UI не содержат формулы расчёта и SQL/файловые операции; вычисления тестируются без запуска графического интерфейса.
